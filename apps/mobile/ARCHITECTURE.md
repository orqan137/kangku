# 강꾸 모바일 아키텍처

## 현재 단계

앱은 오프라인에서도 기능을 확인할 수 있도록 AsyncStorage 기반 로컬 어댑터를 사용한다. 데이터 모델은 서버 동기화로 옮길 수 있게 분리했지만, 서로 다른 휴대폰의 실시간 통신은 아직 연결되지 않았다.

## 공동 필기 원칙

필기장은 전체 배열을 덮어쓰지 않는다. 각 펜 스트로크를 독립적인 불변 객체로 취급하고 아래 연산을 누적한다.

- `stroke.upsert`: 완성된 스트로크 등록
- `stroke.delete`: 특정 스트로크 삭제 tombstone
- `actor.clear`: 요청한 사용자 자신의 레이어만 비우기

모든 연산에는 `lectureId`, `materialVersionId`, `actorId`, `clientId`, `clientSequence`가 들어간다. 서버 연결 후에는 `serverSequence`를 추가해 모든 클라이언트가 같은 순서로 재생한다. 연산 ID로 재전송 중복을 제거한다.

점 좌표는 기기 픽셀이 아니라 PDF 페이지 좌상단을 기준으로 한 `0..1` 정규화 좌표로 저장하고 `pageIndex`로 페이지를 구분한다. 따라서 화면 크기와 해상도가 다른 기기에서도 같은 문서 위치를 가리킨다.

실시간 전송은 두 채널로 나눈다.

1. 미리보기 채널: `stroke.begin`, 30-50ms 단위의 점 묶음, `stroke.end`를 WebSocket으로 전송한다. 일시적인 데이터이며 재접속 복구 대상이 아니다.
2. 영속 채널: 스트로크가 끝나면 압축된 완성 스트로크 하나를 저장하고 방 전체에 확정 이벤트를 보낸다.

재접속 시에는 최신 스냅샷과 그 이후 연산만 내려받는다. 매번 전체 필기를 다운로드하거나 저장하지 않는다.

## 강의자료 버전

강의자료는 수업 생성 전에 반드시 업로드한다. 선택한 PDF는 현재 로컬 앱의 문서 디렉터리에 복사되며, 서버 연결 후에는 객체 저장소의 고유 경로로 업로드한다.

교체는 기존 파일을 덮어쓰지 않고 새 `LectureMaterialVersion`을 만든다.

- `Lecture.activeMaterialVersionId`가 현재 자료를 가리킨다.
- 필기와 개인 저장본은 항상 `materialVersionId`를 가진다.
- 새 PDF로 교체해도 이전 PDF와 이전 필기는 함께 보존된다.
- 수업 중 교체 이벤트를 받은 클라이언트는 새 버전 자료를 받은 뒤 새 필기 레이어로 전환한다.
- 모바일에서는 원본 PDF를 직접 렌더링하고 그 위에 현재 페이지의 필기 레이어를 겹친다.
- 내보낼 때는 화면 캡처 한 장이 아니라 원본 PDF의 모든 페이지에 해당 페이지의 필기를 벡터로 합성한다.

## 서버 권장 구성

- 인증/API: Node.js 기반 API 서버. 현재 아이디/비밀번호를 서버의 Argon2id 해시로 이전하고 이후 Google OAuth를 같은 사용자 계정에 연결한다.
- 영속 데이터: PostgreSQL에 사용자, 방 멤버십, 강의, 자료 버전, 확정 스트로크, 채팅을 저장한다.
- 파일: S3 호환 객체 저장소에 PDF와 완성 필기 PDF를 저장한다.
- 실시간: WebSocket 게이트웨이와 Redis Pub/Sub으로 방 단위 브로드캐스트와 접속 상태를 처리한다.
- 권한: 방 멤버만 읽기/필기, 방장 또는 강의 개설자만 자료 교체, 서버만 `serverSequence` 발급.

## 출시 전 필수 변경

PDF 페이지 기준 정규화 좌표와 페이지별 내보내기는 구현되어 있다. 다만 현재 필기 렌더러는 점마다 React Native `View`를 생성하므로 대규모 공동 필기에는 적합하지 않다. 베타 전에 Skia 또는 네이티브 Canvas의 단일 Path 렌더링으로 교체해야 한다.

서로 다른 기기에서의 실제 동시 필기는 아직 로컬 어댑터만으로 동작하지 않는다. 출시 전에는 위 이벤트 모델을 WebSocket/API 어댑터에 연결하고, 서버 순서 부여·중복 제거·재접속 스냅샷·권한 검증을 통합 테스트해야 한다.
